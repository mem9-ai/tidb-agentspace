# Local agent report trial

Accepted product scope for [GH-210](https://github.com/mem9-ai/tidb.ai/issues/210). Source baseline: `ace7a2d6a7704143936469773561a98db9a0bc2e`. The first release targets a local Codex or Pi session, the public `us-sales-v1` fixture and one isolated report.

- **TR-1 · Start.** Studio copies one instruction with the official skill URL and a concrete free task. The local helper obtains the pinned public sample and saves a readable Markdown report without login, customer keys or billing. Its totals must independently match 240 orders, USD 100,000 total and USD 48,000 in California.
- **TR-2 · Continue.** Within 48 hours, a new process in the same project, including a different agent, finds the existing report without chat history. Product analysis adds Monitors, USD 18,000 and 37.5% of California sales to the same report. Duplicate and concurrent requests preserve completed sections, the identity and the original expiry.
- **TR-3 · Identity.** One OS user, canonical project root and trusted service form a binding. Generate one Ed25519 key, store it only in the current user's native credential store and prove possession against a short-lived single-use challenge. Concurrent local starts serialize. A copied identifier, directory or stale proof grants no remote access.
- **TR-4 · Expiry.** Enforce 48 hours on the server. On the next use of that binding delete its expired local secret, retain the report and never silently enroll a replacement. Provide explicit local removal. With a locked or missing keyring offer a clearly labeled local-only report. Do not fall back to plaintext credentials.
- **TR-5 · Boundaries.** Only bounded sample analysis and a single versioned report may run in a trial. Limit registration and requests. No provider provisioning, uploads, private workspace grants or spending. Keep stable origin/report/revision information for a future owner-confirmed claim. A future budget is independently granted by a payer. Neither workflow ships here.

Verify the actual Studio clipboard, two independent client processes using the native HTTP service, replay, cross-project denial, restart, simultaneous first use and expired-key removal. Report native credential adapters and actual agent hosts exercised separately from automated substitute stores. Existing Workspace Key and 24-hour browser Guest flows retain their contracts.
